## Verdict

**Spec compliance: substantial implementation; narrowly conditional pending the residual corrections in the reconciliation table.** The source implements the complete intended customer journey and uses the approved React/FastAPI/PostgreSQL/Supabase modular monolith. Authentication uses Supabase's verified-user endpoint. Server tenant checks, PostgreSQL policies and composite tenant foreign keys are present. Reports and passport events are append-only for the application role, technician notes are separate, and analysis is saved atomically with history. Manual observations do not enter the telemetry model. Missing frozen-model and live-provider verification are disclosed rather than fabricated.

**Quality: suitable beta foundation after important fixes and verification; not yet an unconditional pilot release.** No directly exploitable HTTP cross-tenant database bypass was found by inspection. Important evidence-quality, identity-display, retry and session-state defects need correction. Native PostgreSQL, Docker and live Supabase/provider verification remain distinct external/runtime gates; this review does not upgrade PGlite PostgreSQL/WASM evidence into native/deployed verification. Tests and browser workflow are being run by the release owner, so no test-suite PASS is asserted here.

## Original important findings

1. **Empty/unsupported SAN telemetry is represented as successful ML screening.** `backend/app/workshop/evidence.py:telemetry_evidence`, especially the unconditional `ml-regions` finding; inherited SAN ingestion also never validates `schema_version`. Executed a pure-function reproduction with 4 and 12 SAN rows, version `UNSUPPORTED-99`, all numeric measurement cells empty, and matching vehicle identity. Both returned quality `accepted`, score 80, model status `insufficient_samples`, feature count zero, and an `ml_screening` finding saying “0 statistically unusual regions identified.” This is an evidence-integrity defect, not just a warning. Minimal fix: validate the supported version and usable finite signal coverage at the workshop boundary, and reject/explicitly label an unavailable model run instead of producing a successful-screening finding. Test short sessions, wholly missing numeric data, unsupported versions and invalid/nonfinite values.

2. **Login silently changes passwords.** `backend/app/workshop/schemas.py:LoginInput` inherits `Input`'s `str_strip_whitespace=True`. Executed `LoginInput(email='a@b.c', password=' secret ').password`; result was `'secret'`. A valid existing Supabase password can therefore never authenticate. Minimal fix: retain password bytes/whitespace, with a login-specific model configuration or field-specific handling; trim email separately if desired.

3. **Analysis retries create duplicate evidence/history.** `frontend/src/Workshop.tsx:JobDetail.analyze` creates `crypto.randomUUID()` inside each attempt. If the API commits but the response is lost, retry submits a new key and creates a second immutable report/passport event. Backend idempotency is otherwise implemented. Minimal fix: retain the key for the same evidence submission through uncertain failures, resetting it only after success or an intentional input change. Exercise a committed-but-lost response.

4. **Historical reports display mutable vehicle identity and can lose demo labeling in print.** `frontend/src/Workshop.tsx:ReportDetail` renders the current `vehicle` record rather than persisted `evidence.vehicle_snapshot`. Editing make/model changes the heading of old evidence reports. A manual report on a demo vehicle has source `manual`, and printing hides the topbar's sole global DEMO label. Minimal fix: render report identity from its saved snapshot and include a persistent report/print DEMO label based on the snapshot. Also expose the saved inspection/observation snapshot when reviewing a report; it is currently persisted but absent from the report display.

5. **Session changes leave prior customer data and unfenced asynchronous results in the UI.** `frontend/src/Workshop.tsx:signout` clears session/workshop/job/report but retains customers, vehicles, jobs, workshops, reports and history. A subsequent sign-in can briefly show the preceding identity's queue/directory, including if new data fetching fails. `openReport`, `openPassport` and `openJob`'s reports request also lack the workshop-change guard used by `refresh`; delayed results can reopen an old workshop's report beneath the newly selected workshop. Minimal fix: clear all tenant state on signout/change and invalidate outstanding results using a session/workshop request generation (or cancellation plus identity checks). Test signout/signin and workshop changes with delayed responses.

6. **Vehicle source identity lock is vulnerable to a concurrent first analysis.** `backend/app/workshop/api.py:edit_vehicle` checks for existing reports before its update, while `save_analysis` locks only the job and reads the vehicle without a row lock. A source-ID/demo-label update can pass its check while the first report is in progress and commit after the report. This bypasses the intended “locked after evidence” rule and leaves current vehicle source identity inconsistent with recorded evidence. Minimal fix: lock the same vehicle row before checking/updating source identity and before taking an analysis vehicle snapshot, with consistent lock order. PGlite demo serialization masks this native multi-connection race; inspect or test with native concurrency when available.

## Lower priority

- `Passport` derives its vehicle from the first history event, so an empty passport loses the selected vehicle identity; pass the selected vehicle explicitly.
- The Passport “View report” callback has no local catch/loading feedback for its first `Promise.all`; a fetch failure may remain an unhandled rejection instead of a useful retry state.
- Workshop creation lacks a pending guard/disabled submission button, so repeated clicks can create multiple workshops. Customer/vehicle forms do disable while saving.
- Deterministic rule details fall back to `str(rule)`, displaying Python dictionary syntax and implementation fields rather than an evidence sentence. Format existing metrics/signals into readable deterministic text without adding new claims.
- The production CSP blocks the Google Fonts import in `styles.css`; system fallbacks render, but typography differs from development. Bundle fonts or use declared local/system typography consistently.
- The main workshop component and backend modules are heavily compressed into long lines and broad `any` types. This raises maintenance cost; keep refactoring separate from release fixes.

The password and insufficient-data findings were reproduced directly; the retry, rendering, stale-state and concurrency findings are code-path analyses. The missing frozen artifact remains an honestly labeled session-fit fallback; its absence is not itself a newly introduced defect.
